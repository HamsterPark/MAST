# 记录与上下文

MAST 保有一份永久的实验记录，与你自己的执行环境在会话之间记不记得住无关。这一篇说明
你的动作会在记录里留下什么、什么不会留下，视觉回路为每个实验留下什么，以及在你开始之前
MAST 已经掌握了哪些上下文、去哪里找它们。

## 记录什么、记在哪

你提交的每一个作业都会署上你的名字写进实验记录，好让后来者 —— 不管是人还是 agent ——
能把你的动作和别人的区分开。从 7.0 起，每个动作的每一步也是如此：动作的各个步骤和外部作业
走的是同一条记录路径。

| 记录 | 字段 | 值 |
|---|---|---|
| v1 `actions` 表 | `context` | `ext:<actor>`（带会话名时是 `ext:<actor>/<session>`） |
| v2 动作记录 | `agent_id` | `ext:<actor>` |
| v2 动作记录 | `thread_id` | `ext:<actor>`（或 `ext:<actor>/<session>`） |
| 动作产生的数据文件 | — | 会被登记，并拷贝进当前实验的文件夹 |

每个作业自己的视图里也带着一个 `recorded` 字段，说的是同一件事：

```json
{"v1": true, "v2_action_id": "...", "experiment_id": "...", "sample_id": "..."}
```

## 没有实验，就什么都不会记录

`v1: false` 表示动作跑的时候没有当前实验，所以它在记录里没有留下任何痕迹 —— 这不是一次
失败，只是不存在。简报的 `recording` 段与每个作业的 `recorded` 字段都会把这件事说清楚；
如果这份工作以后还要能被找回来，先定样品和实验。没有实验时帧照样归档，放在 `no-experiment`
工作区里，但没有任何实验记录指向它们。

## 工作区（7.0 新增）

每个实验都有一个视觉回路的工作区（见[概念](02-concepts.md)）。除了帧档案和 `WORKING.md`，
它还有一份只追加的日志 `events.jsonl`，每个事件一条记录：

| 记录 | 什么时候写 | 内容 |
|---|---|---|
| `act` | 一个动作结束时 | 轮次、动作或技能、给定的参数与换算后的参数、控制器的结果、各个步骤、新帧的 id、动作之后的仪器状态、用时、你写的备注，以及客户端信息：Codex 的代码段 id 与轮次元数据、Claude Code 的 tool-use id、客户端的名称和版本 |
| `observe` | 发出一次观测时 | 它的 id、轮次、显示的是哪一帧，以及起因（看一眼、恢复、等待） |
| `refusal` | 观测闸拒绝一个动作时 | 拒绝代码、动作、客户端信息 |
| `external_frame` | 一张不是你的动作产生的帧归档时 | 帧 id 和 `origin: external` |
| `checkpoint` | 要求做检查点时，或为此存好 `WORKING.md` 时 | 原因 |
| `detector_hit` | 探测器记下一次命中时 | 探测器、帧、它给的消息，以及这次命中是否被 `suppressed` |
| `detector_disabled` | 探测器被自动停用时 | 探测器和原因 |

没有哪条记录里存着令牌。`mast_history` 只读这份日志、什么都不改：`view: "events"` 按轮次返回
动作、外来帧、探测器的命中与停用，以及检查点（用 `start_turn`、`end_turn`、`limit` 选范围）；
`view: "attempts"` 汇总这个实验到目前为止的情况：各类动作做了多少次、失败了几次，有哪些帧和谱。

帧档案 `archive\` 里，每一帧在 `index.jsonl` 里有一行；每一帧还有一个 `.npz`，存着全部通道、
正反两个方向的 SI 数值（没采到的地方是 NaN），以及一个 `.png`，是默认渲染、也就是 agent 最初
看到的那张图。谱额外保留原始的 `.dat` 文件；衍生图如果有数值，也会把绘图所用的数值存下来。
任何东西都不会被淘汰。原始数据文件仍留在控制器保存它们的地方，并照旧登记进实验。

## 找数据（7.0.1 新增）

`mast_list_data`（`GET /data/files`）按时间倒序列出 MAST 能给你的文件；要按内容找，用
`mast_search_data`（`GET /data/search`）。它查的是数据图库（界面里的 `/records/gallery`）建好的
索引，再加上索引里还没有的最新文件（现场读文件头，一次最多 200 个）：

| 条件 | 含义 |
|---|---|
| `ext` | `sxm`（图）、`dat`（谱）、`3ds`（网格谱） |
| `experiment`、`sample` | id（或至少 6 位十六进制字符的前缀），或名字的一部分 |
| `since`、`until` | 开始时间，按仪器电脑的本地时间；`until` 只给日期时包含那一整天 |
| `size_min_nm`、`size_max_nm` | 图或网格谱的宽度 |
| `bias_min_v`、`bias_max_v`、`setpoint_min_pa`、`setpoint_max_pa` | 偏压、设定点 |
| `text`、`tag`、`min_rating` | 文件名、路径或操作员备注里的字；操作员的标签；评级（2 重点、1 可用、-1 排除） |

条件可以任意组合，新的在前（`order: "oldest"` 反过来），用 `n` 与 `offset` 翻页（`total`、
`has_more`）。每条结果给出：

- `path`：交给 `mast_fetch` 的路径。`fetchable: false` 表示它在 MAST 数据出口允许的目录之外
  （图库的目录是操作员配的，可能比数据出口宽），这时请操作员把文件拷进来；
- `experiment`、`sample`：从实验文件夹的结构推出的归属，说不出就是 `null`；
- `frame`：这个文件已在当前实验的帧档案里时的帧号，可以直接 `mast_inspect`、用量尺；
- 尺寸、像素、偏压、设定点、通道，谱的扫描范围、点数与位置，以及操作员的评级、标签、备注；
- `time`（开始）与 `saved`（存盘），本地时间。

`index` 说明索引写于何时、覆盖哪些目录；还没建过索引时，只查现场读到的那些。`live.truncated: true`
表示现场读到了上限，索引之外更旧的文件这次没有查到。`mast_list_data` 的结果里，已在当前帧档案里的
文件同样带 `frame`。

## 简报的各段

`GET /briefing` 是分段的；可以要全部，也可以点名要哪几段：

| 段 | 内容 |
|---|---|
| `status` | 模式、中止标志、仪器锁、连接、实时读数、作业计数，以文字形式给出。 |
| `scope` | 当前实验与样品，以及两者都没有时会发生什么。 |
| `resume` | 这个实验做到了哪一步 —— 与 MAST 自己的 agent 读到的是同一份续工块。 |
| `tip` | 已登记的关于当前针尖的事实。 |
| `instrument` | 仪器档案，以及任何学到的标定值。 |
| `live` | 实时读数，来自缓存快照。 |
| `prefs` | 操作员的默认参数偏好。 |
| `safety` | 当前生效的安全包络，以及任何挂着的停止闩与解除方法。 |
| `recent_actions` | 这个实验里最近的动作，附上各是谁做的。 |
| `recent_files` | 最近的数据文件。 |
| `alarms` | 环境监控的总体状态与最近的告警。 |
| `notes` | 这个实验里最近的笔记，不限作者。 |
| `recording` | 你自己的署名，以及你的动作到底会不会被记录。 |
| `jobs` | 你自己最近的作业。 |
| `operator_requests` | 你向操作员发出的请求，以及所有答复。 |

每段答复的精确形状见 [API 参考](07-api-reference.md)。

## 笔记与 MAST 的记忆

你写的笔记会落进与 MAST 自己内部 agent 读的同一个记忆库，它们会在之后的轮次里自动召回它 ——
你不需要另外告诉任何人它存在。反过来也一样：你可以检索 MAST 自己的 agent 写下的笔记，这往往
是了解「之前那次会话已经查明了什么」最快的办法。

`GUIDE.md` 和 `WORKING.md` 是另一回事：它们是 agent 留给自己的文件，整篇读、整篇写，一个全新的
会话就从它们开始。操作员和 MAST 自己的 agent 也该知道的发现，写成笔记；你的计划和你当下的理解，
放在这两份文件里。

## 问操作员

向操作员提的一个问题或请求是**异步**回答的。不要在这里等着：继续做那些不依赖这个答案的事，
过一会儿再回来看（或者读简报的 `operator_requests` 段），不要把整个会话都堵在一个可能要
过一阵子才会来的答复上。在 `mast_wait` 的条件里加上 `{"type": "operator_reply"}`，答复一到
就会叫醒你，和你在等的其他事情一起。

## 交接

交接报告会写进 MAST 的文档库，操作员能在报告页看到它 —— 它不是一份只有你自己能看的私人
日志。每结束一次会话就写一份，哪怕这次很短：你跑过的作业、记在你名下的动作、你自己写的
笔记，都会自动汇总进去，和你给的总结与下一步一起。交接之前先存好 `WORKING.md`，下一次会话
才能从你停下的地方接着做。

## 运行器的记录（7.0 新增）

每次无人值守运行都有自己的文件夹，在 MAST 项目目录下的 `experiments\vista\runs\<run id>\`：
`status.json`（这次运行、它启动的每个会话、用量合计，以及所有没拿到结果的工具调用）、系统
提示词，以及每个会话的启动命令、设置、输入和输出流（图像数据换成了哈希和大小）、错误输出和
hook 日志。`GET /runner` 列出各次运行，包括更早的；MAST 停下时还在进行的运行会显示为
`interrupted`。

## 重启之后

MAST 进程重启时还在跑的作业，记录里会标成 `lost_on_restart`，绝不会被重放 —— 没有人，
包括 MAST 自己，知道它在仪器上究竟做到了哪一步。决定下一步做什么之前先重新读一遍简报；
不要凭空再提交一次。工作区会连同帧档案、笔记、历史和轮次计数一起回来；观测令牌不会，所以
下一个动作之前先调 `mast_observe`。
