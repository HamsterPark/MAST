# 概念

下面这些概念说明 [API 参考](07-api-reference.md) 里每个端点到底在做什么。先读一遍这篇，
后面的 [运行规则](03-operating-rules.md) 会因为有了这些名词而更好懂。

## 技能与技能元数据

**技能**是一个有名字、已注册的动作：一次读取（读偏压）、一次写入（设一帧扫描参数）、
一个由若干技能组成的组合，或者一次不碰硬件的纯分析。每个技能都带元数据，技能卡
（`GET /skills/{name}`）会把它们完整地给出来：

| 字段 | 告诉你什么 |
|---|---|
| `category` | `read` / `write` / `composite` / `analysis` —— 说的是形状，不是风险 |
| `safety_level` | `auto` / `confirm` / `dangerous` —— 见下文的[安全级](#安全级) |
| `parameters` | 每个参数的类型、单位、是否必填、默认值，以及 `min`/`max` 范围或一份允许取值列表 |
| `preconditions` | 执行前要核对的仪器状态条件（例如「当前没有扫描在跑」） |
| `capabilities` | 电脉冲、修针一类的能力标签，运行模式闸会读它 —— 见下文 |

带量纲参数的范围用 SI 基本单位给出（伏特、安培、米、秒）；有些参数除了裸浮点数还接受
`"5n"` 这样的 SI 前缀字符串 —— 技能卡的 `si_params` 会说哪些参数接受、前缀是否必须。
不要从「这个技能做什么」去猜它的名字：按动作检索，[运行规则](03-operating-rules.md)
里说明了这一点。

## 组合技能

**组合技能**是一份把若干已有技能编成的图，表达成 JSON 格式的 `CompositeSpec` —— 是数据，
不是代码。它经过的闸门与任何其他技能完全一样。它生效的安全级，是 spec 自己声明的级别与它
所有步骤里最严格那个之间**更严的一个**；它的能力标签是所有步骤标签的**并集** —— 所以声明
只能收紧步骤本身已经是的那个级别，不能放松：一份声明成 `dangerous` 的 spec，哪怕每一步都是
`auto`，依然是 `dangerous`；一份声明成 `auto`、却含有一步 `confirm` 的 spec，跑起来就是
`confirm`；一份含有针尖处理步骤的 spec 会带上那个能力标签，于是 SAFE 拒绝整个组合技能，跟
它拒绝那一步单独执行时一模一样。怎么写一份见 [造技能](05-authoring-skills.md)。

## MAST 的仪器 agent 工具（7.0.1 新增）

除了技能，MAST 自己的仪器 agent 还用一批不是技能的工具：它们读写的是 MAST 的记录，不是仪器。
从 7.0.1 起外部 agent 也有这一套，不分角色（不开放的两类见本节末尾）。`GET /skills/search` 把它们和技能列在一起（来源
`仪器 agent 工具`，来源代号 `ic_agent_tool`），`GET /skills/{name}` 给出同样形状的卡片（另带它的
`family`），`POST /jobs` —— 或者不带令牌的 `mast_run` —— 把它作为 `kind` 为 `tool` 的作业来跑，
入账与技能调用相同。

| 家族 | 工具 |
|---|---|
| 实验与样品 | `list_experiments`、`list_samples`、`start_experiment`、`switch_experiment`、`start_sample`、`switch_sample`、`clear_sample`、`end_experiment`、`end_sample`、`rename_experiment`、`rename_sample` |
| 针尖登记 | `get_current_tip`、`list_tips`（只读；登记、修改、注销由操作员在界面上做） |
| 扫描地图与粗动地图 | `get_map_analysis`、`get_next_scan_position`、`get_markers_near`、`get_coarse_map`、`mark_area_used` |
| 计划 | `plan_scan_batch`、`create_plan`、`approve_plan`、`list_plans`、`get_plan_progress`、`advance_plan`、`pause_plan`、`resume_plan`、`show_plan_on_map`、`clear_plan_on_map` |
| 知识与指导 | `query_knowledge`、`get_workflow_advice`、`get_skill_guidance`、`get_literature_parameters`、`get_fault_diagnosis`、`get_noise_reference`、`get_measurement_template`、`search_deep_reference`、`read_reference_section` |
| 文件与文档 | `get_latest_scan_info`、`load_scan_file`、`list_documents`、`load_document`、`survey_environment` |
| 技能市场 | `search_skill_market`、`recommend_skill_subscription` |
| conduct | `conduct_status`、`conduct_list`、`conduct_compile_from_plan`、`conduct_post_op`（只收 `pause`、`abort`、`takeover`） |

它们的足迹是 `mast-read` 或 `mast-write`。没有一个自己发控制器命令（`conduct_post_op` 的 `abort` 会让
指挥线程退针，卡片的 `sub_skills` 里写着 `SafeRetract`）；实验、针尖、扫描地图、计划、知识与
扫描文件这几类工具每次调用会刷新一次 Nanonis 的保存目录（`Util_SessionPathGet`，缓存 15 s，只读；
卡片的 `verbs` 里列着它），与它们给 MAST 自己的 agent 用时完全一样。外部面多守三条：改当前实验或样品的工具在仪器被占用时被拒，与 `POST /scope` 一样；文件路径必须
在数据搜索目录或实验根目录之内，与 `/data/*` 一样；`conduct_post_op` 只收叫停与收回的 op。

不开放的有两类，卡片和提交都回 403 `not_offered` 并说明理由：

- 会把活交给 MAST 内部 agent 的：`spawn_background_task`、`request_activation`、`conduct_create`、
  `conduct_approve`，以及 `conduct_post_op` 的 `start` 与 `resume`。活由外部 agent 自己干，这些工具
  要用的能力都能直接用到。
- 替操作员陈述一件发生在仪器旁的事的：`register_tip`、`update_tip`、`remove_current_tip`（换了针）与
  `record_coarse_move`（在 Nanonis 里手动粗动过）。登记它们会清掉安全联锁或学习量：补记粗动会清空同一点
  撞针两次之后的封锁，登记或注销针尖会清掉 qPlus 撞针判据的振幅基线，修针的缺省剂量也跟着登记走。远端
  的 agent 看不见那件事有没有发生。请操作员在 MAST 界面上做（针尖卡片、扫描地图页），用
  `mast_ask_operator` 请他。

## 执行收口

不管一次技能调用从哪条路进来 —— 一个直接的作业、一个组合技能里的一步、还是 MAST 自己
内部的 agent —— 在碰到仪器之前都会经过同一串检查：

1. **中止检查** —— 中止标志已置位就直接拒绝。
2. **样品门** —— 产数据的技能需要一个当前样品（见下文）。
3. **运行模式闸** —— SAFE 或 SEMI 可能拒绝针尖处理类调用（见下文）。
4. **五条硬闸** —— 在这条路径上无条件拒绝、没有批准可等的物理保护：开环粗动 Z 朝样品
   进针；关闭一项硬件保护（SafeTip、Z 软限位）；改写全局 bias/current 标定；设置粗动马达
   的驱动电压或频率；绕开有防护的换位技能、直接下裸横向粗动指令。你做什么都改变不了这
   五条 —— 它们不是冲着你来的。
5. **全局安全包络** —— 每一个带量纲的参数都会拿去跟管理员配置的范围核对，不管技能自己
   的元数据怎么写。
6. **参数校验** —— 技能自己的 `validate_params`。
7. **前置条件** —— 技能声明的前置条件，拿当前仪器状态核对。没通过时，会再向仪器读一次
   状态、重新核对一遍；这次重读还是不过，拒绝就维持原判。
8. **仪器仲裁** —— 仪器锁（见下文）。

八步全过，技能才真正碰到仪器。任何一步的拒绝都不是 HTTP 错误：它是一份正常的、结构化的
答复 —— 每一种长什么样见 [排障](08-troubleshooting.md)。

## 安全级

在这条路径上，`safety_level` 是信息性的，不是内置的刹车 —— 把它读成「这件事值得多少
小心」，而不是「MAST 会在这里替你停下来等人」：

| 级别 | 在外部 agent 路径上会发生什么 |
|---|---|
| `auto` | 立刻执行。读取，以及小幅、可重复的写入。 |
| `confirm` | 同样立刻执行 —— 这条路径上没有人可以确认。扫描参数、谱学、修针、有防护的横向
  粗动通常是这一级。 |
| `dangerous` | 同样执行 —— 记录下来，事后通知操作员。不会被拦下，也不等任何批准；这一级
  很少见（全目录只有几个技能是这一级）。 |

上面那五条硬闸是唯一不管 `safety_level` 写什么都无条件拒绝的调用。其余一切都会执行，
意味着一个动作是否明智由**你**来判断，不是这个级别替你判断的。

## 运行模式

**运行模式**是操作员的全局设置，`GET /status` 以 `mode` 字段报告（没有任何东西绑定过
就是 `unknown`）：

| 模式 | 允许什么 |
|---|---|
| `safe` | 完全不许针尖处理：每一次电脉冲、每一次机械修针都会被拒，哪怕藏在一个组合技能
  深处。扫描、谱学与其余一切测量照常进行。 |
| `semi` | 允许浅层、纯机械的修针；下压太深会被拒。电脉冲会真的执行并被记进日志 ——
  这一级不会悄悄拦它。 |
| `auto` | 一切照上面每一道其他闸门放行。 |

你不能从外部 agent API 改这个模式，也不该想办法绕过去：如果一个任务需要比当前模式更多
的权限，去问操作员（见[运行规则](03-operating-rules.md)）。

## 样品门

产数据的技能（扫描、谱学）需要一个当前样品；只读状态的技能，以及安全补救动作（停止、
退针、撤回）从不需要。技能归类判不准时，这道门**朝放行方向走** —— 这是有意的：一条没
归属样品的记录是记账损失，而在错误的时刻拦下一个安全补救则是不能接受的代价。跑任何产
数据的动作之前先用 `POST /scope` 定样品。

## 仪器锁

同一时刻只有一个调用方驱动物理仪器。锁按每次技能调用来取，可重入（组合技能不会卡在自己
的子步骤上），只读、分析与停止/撤回类技能完全不取它。取不到锁的调用方**被拒绝、绝不排队** ——
`refused_busy` 会说清现在是谁在开车。这是刻意的：一次长扫描绝不能在背后攒起一条看不见的
等待队列，而被告知「另一方在开车」的 agent 应该等等再来查看，而不是空转重试。

## 中止与取消

存在两种作用域不同的停止机制。进程级的**中止标志** —— 也就是急停闩 —— 由 E-STOP（操作员
自己按的按钮，或者你自己调的 `POST /estop`）、一次环境告警，或某个硬件安全信号置位；操作员
只是停掉 MAST 自己的某个 agent 运行，并不会置位它。闩置位期间，任何技能调用都会在开始之前
就被拒 —— 只读与停止类技能都不例外 —— 因为置位它的那次 E-STOP 已经停了运动、退了针，一个
停止类技能已经没有什么可做的了；只有操作员能解除它。（状态与简报调用在此期间仍然照常回答：
它们报告的是缓存状态，不是在跑一个技能。）`GET /status` 把这个闩报告成
`abort: {set, emergency, why}`。

单个作业级别的**取消**（`POST /jobs/{job_id}/cancel`）是一种更窄、协作式的机制，只作用于
一个作业：技能在下一次检查处停下，这意味着卡在单条 Nanonis 调用里的技能要等那条调用返回
才会停。要立刻物理停止运动，跑一个停止类技能（永不受仪器锁限制），不要指望取消。

## 作业与它们的状态

经 `POST /jobs` 提交一个技能会立刻带着 `job_id` 返回；工作在它自己的线程里进行，你轮询
拿结果：

| 状态 | 含义 |
|---|---|
| `queued` / `running` | 还没结束 —— 继续轮询。 |
| `succeeded` | 技能自己报告成功。 |
| `failed` | 技能报告失败，或者在上面某道闸门被拒（`refused_by` 说是哪一道）。 |
| `refused_busy` | 仪器锁被别人占着；什么都没跑，也没有被排队。 |
| `cancelled` | 在成功结束之前被 `POST /jobs/{job_id}/cancel` 停下。 |
| `crashed` | 作业自己的线程意外失败；把结局当作未知处理。 |
| `lost_on_restart` | 作业还在跑的时候 MAST 重启了。它绝不会被重放，也没人知道它在仪器上
  做到了哪一步。 |

等待时客户端自己的超时不算这些状态之一：不管你还看不看着它，作业都会继续在 MAST 上跑 ——
这正是要有作业机制、而不是一次长 HTTP 调用到底的全部理由。每种状态该怎么应对见
[运行规则](03-operating-rules.md)。从 7.0 起，视觉回路里的每一个动作也是一个作业（种类
`act`），状态完全相同；`mast_wait` 在服务端等任何一个作业结束，不用再轮询（见下文）。

## 视觉回路（7.0 新增）

VISTA 是给多模态模型用的一套视觉回路。模型拿到的不再是某个图像分类器写出的文字摘要，而是
仪器自己的图像；它可以把任何一张旧帧无损地调回来、放大其中一块，读出精确数值，用工具做测量，
还有两份自己写的笔记。7.0 把这套回路放进了 MAST 服务端，所以帧档案、测量和一动一观的规则
对每个客户端都是同一套。

### 工作区

每个 MAST 实验有一个工作区。用 `mast_scope` 选定的当前实验，决定了每个 VISTA 工具读写的是
哪个工作区：`exp-<实验 id>`；没有当前实验时是 `no-experiment`。换实验，帧档案、`WORKING.md`、
历史和轮次计数也跟着一起换。工作区放在 MAST 项目目录（装好的 MAST 就是安装目录）下的
`experiments\vista\<workspace id>\`，重启之后会重新打开。

| 工作区里 | 存的是什么 |
|---|---|
| `archive\` | 这个实验的每一帧，无损（见下文） |
| `notes\WORKING.md` | agent 在这个实验里的工作记忆 |
| `events.jsonl` | 每个动作、观测、拒绝、外来帧、检查点、探测器命中、探测器停用各一条记录 |
| `detectors.json` | 这个实验的分析探测器，以及它们最近的命中 |

`GUIDE.md` 记的是长期有效的经验，所有实验共用这一份：`experiments\vista\GUIDE.md`。

### 帧与帧 id

控制器存下的每一个新数据文件（扫描 `.sxm`、谱 `.dat`）都会连同所有通道、正反两个扫描方向一起
以 SI 数值归档，随时可以重新渲染、放大、再读一遍。帧 id 写明了轮次和种类：`t0007.s0` 是第 7 轮
存下的第一张扫描；`p` 表示一张还在扫的图的中途快照，`d` 是一条谱，`m` 是测量工具生成的衍生图
（剖面图、傅里叶谱、差分图）。轮次数的是这个工作区里被接受的动作。每一帧都记着它的 `origin`：
你的动作产生的帧是 `act`，从别处来的帧是 `external` —— 来自 MAST 的界面、操作员、MAST 自带的
内部 agent，或者另一个客户端。

一次观测最多带一张图：新扫出的最新那张扫描图，没有的话就是新测的最新那条谱。其余的新帧列在
观测的文字里，用 `mast_inspect` 可以看其中任何一张。

### 显示像素、扫描坐标系与网格

这里有两套坐标：

- **显示像素：** 帧的完整图像渲染出来之后的位置。原点在左上角，x 向右，y 向下。小的帧按整数
  倍放大（每个扫描像素占整数个图像像素，不做平滑）；每张图都会说明它的像素与扫描像素、与纳米
  之间怎么换算。
- **扫描坐标系（nm）：** 仪器自己的横向坐标，已经计入这一帧的中心和旋转角。针尖就是在这个坐标
  系里移动的。它的 y 轴朝上，和显示像素正好相反。

动作和测量工具两种位置都接受：`{"x_nm": .., "y_nm": ..}`，或者某张已归档帧上的显示像素
`{"frame": "t0007.s0", "x": .., "y": ..}`，后者按那一帧自己的几何换算。你永远不需要手算。扫描
图上叠着一层淡琥珀色的网格，从帧的左上角起每 `grid_nm` 纳米画一格；格距写在图的标签里，放大
后会变细。网格是用来目测位置和尺寸的坐标纸；精确的数由读数和测量工具给出。从旧帧上取的位置
可能已经过时：样品会漂移，压电陶瓷会蠕变。

### GUIDE.md 与 WORKING.md

agent 写给自己看的两份 Markdown 文件。它们存在 MAST 服务端，而不是客户端的上下文里：

| 文件 | 存什么 | 谁共用 | 长度上限 |
|---|---|---|---|
| `GUIDE.md` | 对仪器、样品、针尖长期有效、可以修订的认识 | 所有实验、之后的每一次会话 | 65,536 个字符 |
| `WORKING.md` | 当前的计划、下一次预期看到什么、还没解决的矛盾、还要用到的帧 id | 当前实验 | 16,384 个字符 |

会话一开始把两份都读一遍（`mast_read_guide`、`mast_read_working`），用 `mast_write_guide` 和
`mast_write_working` 整篇重写。上下文换掉之后，留下来的就是它们：一个全新的会话 —— 客户端
压缩了上下文、崩溃之后，或者运行器开的下一个会话 —— 都从 `GUIDE.md`、`WORKING.md` 和最新的
观测重新开始。它们和 MAST 的笔记（`mast_note_write`）不是一回事：笔记进的是 MAST 的记忆库，
给 MAST 自己的 agent 和操作员看。

## 一动一观（7.0 新增）

一个动作只有在上一个动作的结果送到 agent 手里之后才能执行。MCP 服务器看不到模型到底看了
什么，所以 MAST 用一个**观测令牌**来执行这条规则：

- MAST 发出的每一次观测都带一个新令牌 `next_token`，形如 `K7QM-29XA`：动作的结果、
  `mast_observe`、带回已结束动作或新帧的 `mast_wait`，以及 `observe_first` 拒绝里附带的那次
  恢复观测，都是如此。
- 下一个仪器动作必须把它作为 `after` 带上。动作一旦被接受，令牌就用掉了：一个令牌只能用一次。
- 每个 MAST 进程只有一个有效令牌，因为仪器只有一台。它绑定在拿到它的那个客户端会话（一条
  MCP 连接）上。一旦发出更新的观测（不管是发给你还是发给别的客户端），或者来了一张不是你的
  动作产生的帧，它就作废。

受这道闸管的：`mast_act`，以及用 `mast_run` 跑的驱动仪器的技能。永远不受它管的：只读、分析、
帧档案与测量工具，还有补救动作 —— `StopScan`、`WithdrawTip` 这类停止与退针技能、`mast_cancel`、
`mast_emergency_stop`。一个会话一旦用过视觉回路，`POST /jobs` 就会以 `use_act` 拒绝它驱动仪器的
技能；这些技能改走带 `after` 的 `mast_run`，或者 `mast_act`。从不碰视觉回路的调用方，比如一段
6.5.0 时写的脚本，行为和以前完全一样。

### 拒绝

拒绝什么都不执行，也不推进轮次。检查按下面的顺序进行，第一条不满足的就是答复（HTTP 409）：

| 代码 | 含义 | 怎么办 |
|---|---|---|
| `session_closed` | 操作员停掉了这个会话（运行器的叫停） | 不要再做动作；写一句简短的总结收尾 |
| `act_in_flight` | 另一个动作还在执行，不论是哪个会话的；答复里给出它的 `job_id` | 用 `mast_wait` 等那个作业，看它的观测，然后再动 |
| `same_code_cell` | 这个 Codex 代码段已经执行过一个动作 | 结束这段代码，看那个动作的观测（`image()`），在新的一段里再动 |
| `checkpoint_requested` | MAST 要求先做检查点 | 用 `mast_write_working` 存好 `WORKING.md`；在此之前只有笔记工具能用 |
| `observe_first` | `after` 没带、已经用过、比最新观测旧，或者是发给别的会话的 | 拒绝里附着最新的观测和一个新令牌：看它，然后用这个令牌再动 |

`observe_first` 同时也是丢了令牌的客户端回来的路 —— 比如上下文被压缩之后，或者它的 MCP
服务器、MAST 重启之后：调用 `mast_observe`，或者直接读拒绝带回来的那次观测，看过之后用它的
令牌行动。

### Codex 的 Code Mode

在 Code Mode 里，Codex 的模型用 JavaScript 调工具。结果先落进一个变量，图像要等代码对它调用
`image()`，才会送到模型眼前。同一段代码发出的每一次调用都带着同一个 item id，所以服务端每段
代码最多接受一个动作。行得通的做法是：一段代码里只做一个动作，对它的观测调用 `image()`，结束
这段代码，想清楚，再在下一段里带着新令牌行动。

### 严格模式

打开严格模式（操作员启动 MAST 时设 `MAST_VISTA_STRICT=1`）之后，下一个令牌根本不出现在文字里：
它印在观测图下方的一条横带上，文字里写的是 `"next_token": null, "token_on_image": true`。没有
帧图像的观测这时会附一张小卡片图，上面是仪器状态和令牌。严格模式默认关闭。令牌的字母表去掉了
容易看混的字符（没有 0 和 O、1 和 I、2 和 Z、5 和 S、8 和 B），引用时大小写、空格和中间的横杠
都无所谓。

令牌是一个防止「没看就动手」的协议，**不是**安全边界：本机上的任何进程都能直接调 MAST 的
HTTP API。安全仍然靠 MAST 的安全闸。

## 动作与等待（7.0 新增）

一个动作以种类为 `act` 的 MAST 作业运行，走的是和所有技能相同的执行层：按 `request_id` 幂等、
取消、作业日志、撞锁拒绝都照样适用，每一步都像外部作业一样记进记录。`mast_act` 最多等它
`wait_s` 秒（默认 45，最多 50）；到时还在跑的动作会带着 `state: running` 和它的 `job_id` 返回。
用 `mast_wait` 等这个作业来拿它的观测，在此期间不要再做动作：第一个动作结束之前，第二个会以
`act_in_flight` 被拒。

`mast_wait` **在服务端**等，直到某个条件触发，最长 `timeout_s` 秒（默认 600，最多 840）：

| 条件 | 字段 | 什么时候触发 |
|---|---|---|
| `job` | `job_id` | 这个作业（动作或普通作业）结束了 |
| `frame` | — | 有一张新帧归档 |
| `alert` | `min_level`：`info`、`warning` 或 `critical` | 出现不低于这一级的告警：异常、电流监控，或 conduct（多日实验引擎）发出的告警 |
| `operator_reply` | `request_id`（可选） | 操作员答复了这个请求，或者任何一个请求 |
| `detector` | `detector_id`（可选） | 有探测器记下一次命中 |
| `timer` | `seconds` | 过了这么多秒 |

答复里列着触发了什么、是否超时、等了多久，以及一个 `cursor`。如果触发的是一个已结束的动作或
一张新帧，答复还会带上那次观测，连同图像和一个新令牌。同一条连接上的下一次 `mast_wait` 会从
上一个游标接着等（也可以用 `since` 指定），所以两次等待之间的事件一个都不会漏。一次等待可能
长达 14 分钟，所以客户端的 MCP 工具超时至少要设 900 s（Codex：`tool_timeout_sec = 900`）。
中断一次等待不会改变 MAST 上的任何东西。

## 探测器（7.0 新增）

**分析型探测器**是你写的一小段 Python 函数 `def detect(frame)`，MAST 会对每一张新归档的、属于
你指定种类（`applies_to`）的扫描或谱跑一遍。它在一个独立的解释器里运行：碰不到仪器，原始数据
受保护，有时间上限和内存上限。`frame` 提供 `kind`（`scan` 或 `spectrum`）、`fid`、`channels`
（通道名对应正向扫描的二维数组，SI 单位，第 0 行是上边缘，没采到的地方是 NaN）、`backward`、
`meta`（几何、偏压、设定点、单位）；谱还有 `columns` 和 `units`。没命中就返回一个假值，命中就
返回 `True` 或 `{"hit": bool, "message": str, "value": ...}`。命中会被记下来，并结束一个等
`{"type": "detector"}` 的 `mast_wait`。

| 限制 | 数值 |
|---|---|
| 每个实验同时启用的探测器 | 8 个 |
| 每帧的运行时长 `max_runtime_s` | 默认 20 s，最多 120 s |
| 自动停用 | 连续出错 5 次，或者一小时内命中超过 30 次 |
| 唤醒次数 | 所有探测器合计每小时最多 60 次；再多的命中照样记下，标成 `suppressed`，但不唤醒任何人 |

探测器从不动手。要对一次命中作出反应，得你自己动：用 `mast_act`，或者用 `mast_run` 跑一个
组合技能。**动作型探测器**说的正是这件事：一个组合技能（`mast_composite_save`），命中需要时由你
来跑，和任何技能一样要过安全闸。新写的分析型探测器，先在一张已归档的帧上试过再依赖它：
`mast_detectors`，`op` 填 `test`，带上 `detector_id` 和一个 `frame`，比如 `t0007.s0`。

## 运行器（7.0 新增）

运行器让 MAST 无人值守地带着一个 agent 干活。它自己启动 Claude Code 会话（`claude -p`），
MAST 的 MCP 服务器是这些会话唯一的工具来源，并让它们一直跑到任务结束。它是操作员的工具，经
HTTP 启动（`POST /api/ext/v1/runner/start`，带上任务），同一时刻只跑一个；没有哪个 MCP 工具
能启动它。

- **只走订阅。** 运行器会把 `ANTHROPIC_API_KEY` 和 `ANTHROPIC_AUTH_TOKEN` 从会话的环境里去掉，
  任何报告了 API key 来源的会话都会被它结束：那台电脑上的 Claude Code 必须用 Claude 订阅登录。
- **检查点与新会话。** 一个会话用完了它的图像额度，或者 Claude Code 要压缩上下文了，运行器就
  要求做一次检查点：在 `WORKING.md` 写好之前只有笔记工具能用。之后一个全新的会话从
  `GUIDE.md`、`WORKING.md`、任务和最新的观测开始。
- **操作员叫停。** `POST /api/ext/v1/runner/{run_id}/stop` 立刻关闭这个会话，它的动作从此以
  `session_closed` 被拒；然后运行器打断 Claude Code，以 `stopped_by_operator` 结束这次运行。
- **每个调用都有回音。** 运行器核对每一次工具调用都拿到了结果。没拿到结果的调用会被记下来
  （它的作业在 MAST 上照样跑完），下一个会话会被提醒先查 `mast_jobs` 和 `mast_wait`。

Codex 的运行器排在之后的某个 7.0.x 版本；在那之前，Codex 用于交互使用。

## 文献检索（7.0 新增）

`mast_literature_search` 按语义检索 MAST 的文献知识库 —— 也就是操作员的论文库 —— 不碰仪器。
每条结果给出标题、年份、期刊、DOI、相关度分数和一段摘要节选。查已发表的数值和做法（晶格常数、
吸附位、谱学特征、针尖处理）时用它，并引用 DOI。`degraded: true` 表示只做了关键词匹配，或者
这台机器上没有文献库。
